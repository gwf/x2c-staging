Everyday values and operations.

Values, text, and collections. Read down the page or choose an example from the index.

one value

One value, many kinds.

A Var holds a number, text, or a collection. Operators and methods let you work with the value it holds, while ordinary C types remain available when you want them.

examples/love/values.xlink
#include <assert.h>
#include <math.h>

int main(void) {
  // Var holds different kinds of values.
  Var count = 42, ratio = 2.5, name = "Ada";

  // Ordinary operators work on Vars.
  Var next = count + 1, full = name + " Lovelace";

  // Vars format themselves with %s.
  printf("%s %s %s\n", next, ratio, full);

  // Test Var properties at runtime.
  assert(count is int && ratio is double && name is String);

  // Types are checked statically and dynamically as needed.
  int whole = count; double part = ratio;

  // %d and %f also convert Vars.
  printf("%d %f %f\n", count, ratio, sin(ratio));
  return 0;
}

two kinds
Equal contents. Distinct identities.


Strings, Lists, and Symbols share equal values. Arrays and Maps are mutable objects: two separate Arrays can have equal contents without being the same Array.


== compares contents; === compares identity. String and List keys let you retrieve a Map entry using an independently constructed equal value.


examples/love/two-kinds.xlink
#include <assert.h>

int main(void) {
  // Values: equal content is the same object, so == is a pointer compare.
  String greeting = "hel" + "lo", word = "hello";
  List pair = %(1 2), twin = cons(1, cons(2, NULL));
  assert(greeting == word && pair == twin && pair === twin);

  // Objects: Arrays and Maps have identity; copies of the handle share it.
  Array scores = [7, 3, 9], same = scores, other = [7, 3, 9];
  assert(scores == other && scores !== other);
  same.push(5);
  assert(scores == same && scores === same);
  assert(scores != other && scores !== other);

  // Equal Strings and Lists find the same Map entry.
  Map seen = {(greeting): 1, (pair): 2, done: other.len()};
  printf("%s %s %s\n", seen["hello"], seen[%(1 2)], seen[<done>]);
  return 0;
}

collections
Different containers, familiar operations.


Lists, Arrays, and Maps serve different purposes. Their shared operations let you transform a sequence, rank values, and look up a result without rebuilding those operations for each container.


examples/love/collections.xlink
#include <assert.h>

int main(void) {
  // Lists are immutable and share structure; cons is constant time.
  List prices = %(3 5 8), extended = cons(2, prices);
  List doubled = extended.map(%!(price) => price * 2);
  assert(extended.cdr() == prices && doubled == %(4 6 10 16));

  // Arrays grow and mutate in place; copy first to keep the original.
  Array scores = [7, 3, 9];
  scores.push(5);
  Array ranked = scores.copy().sort().reverse();
  assert(scores == [7, 3, 9, 5] && ranked[:2] == [9, 7]);

  // Maps grow on write and tell absence from a stored zero.
  Map stock = {tea: 12, sugar: 0};
  stock[<tea>] -= 2;
  stock[<cocoa>] = 4;
  Var sugar;
  assert(stock.try_get(<sugar>, sugar) && sugar == 0);
  assert(stock.getdefault(<milk>, -1) == -1 && !stock.contains(<milk>));
  printf("%s %s %s\n", doubled.repr(), ranked.repr(), stock[<tea>]);
  return 0;
}

literals
Data you can read.


Describe nested data directly with collection literals. The punctuation shows how the pieces fit together, and expressions supply the values that vary.


examples/love/literals.xlink
#include <assert.h>

int main(void) {
  Map workshop = {
    title: "Make a tiny game",
    topics: %(graphics sound games),
    venue: {
      name: "The Maker House", room: "Studio 2", seats: 24,
      address: { street: "12 Garden Lane", city: "Bristol" }
    },
    hosts: [
      { name: "Ada", role: <instructor>, skills: %(graphics games) },
      { name: "Sam", role: <mentor>, skills: %(music sound) }
    ],
    pricing: { currency: "GBP", standard: 35.0, student: 15.0 },
    bring: ["A laptop", "Headphones", "An unfinished idea"],
    sessions: [
      { title: "Draw a world", minutes: 45,
        project: { width: 320, height: 240, colors: 16 } },
      { title: "Make it move", minutes: 60,
        controls: { left: <a>, right: <d>, jump: <space> } },
      { title: "Add some sound", minutes: 30,
        audio: { channels: 2, volume: 0.75, rate: 44100 } }
    ]
  };
  Map venue = workshop[<venue>];
  Map address = venue[<address>];
  Array hosts = workshop[<hosts>];
  Map host = hosts[0];
  Map pricing = workshop[<pricing>];
  Array sessions = workshop[<sessions>];
  Map first = sessions[0], last = sessions[2];
  Map project = first[<project>], audio = last[<audio>];
  assert(venue[<seats>] == 24 && address[<city>] == "Bristol");
  assert(host[<skills>] == %(graphics games));
  assert(pricing[<student>] == 15.0 && pricing[<currency>] == "GBP");
  assert(project[<width>] == 320 && audio[<volume>] == 0.75);
  assert(workshop[<topics>] == %(graphics sound games));
  return 0;
}

text
Text is something you work with.


Split an HTTP request, select a path component, and format the result. Stripping, splitting, interpolation, and joining turn text processing into ordinary expressions.


Strings are immutable values, so transformations produce a result without changing the original.


examples/love/strings.xlink
#include <assert.h>

int main(void) {
  String line = "  GET /docs/guide/values.html  ";

  // Slice, strip, split, and case-fold; the original is untouched.
  String request = line.strip();
  (String method, String path) = request.split(" ");
  assert(line.len() == 31 && method == "GET");

  // Interpolate values and expressions in place.
  String title = path.split("/").last().str().replace(".html", "");
  puts(%"$method $title ($(path.len()) bytes)");

  // A switch on a String selects its case by content.
  switch (method.lower()) {
    case "get":  puts("read it");  break;
    case "post": puts("write it"); break;
    default:     puts("refuse it");
  }

  // Join and repeat build text; equality is one pointer compare.
  String rule = "-".repeat(3) + " " + ", ".join(%("a" "b" "c"));
  assert(rule == "--- a, b, c");
  puts(rule);
  return 0;
}

names
Give a value a name.


Symbols provide named values for states, keys, and choices. An ordered vocabulary also gives related names an order, so a program can describe its domain without relying on unexplained numbers.


examples/love/symbols.xlink
#include <assert.h>

int main(void) {
  // Names are values, without declaring enum constants.
  Symbol running = <running>, state = <queued>;

  // Symbol literals are constants, so ordinary C switch works.
  switch (state) {
    case <queued>:  puts(%"$state: waiting for a worker"); break;
    case <running>: puts(%"$state: doing the work"); break;
    default:        puts(%"$state: no work left");
  }

  // An ordered vocabulary, built entirely at compile time.
  SymbolSet stages = %<queued running done>;
  assert(stages.contains(state) && !stages.contains(<failed>));
  state = stages[stages.index(state) + 1];
  assert(state == running);

  // Iterate in declared order and recover each name's text.
  foreach (Symbol stage in stages)
    printf("%d: %s\n", stages.index(stage), stage.str());
  return 0;
}

loops
Walk the data, name its parts.


foreach walks a container while destructuring gives each part a name. Pattern conditions select the orders that matter, and an iterator chain totals their quantities.


examples/love/loops.xlink
#include <assert.h>

int main(void) {
  Array orders = [%(tea 2 "Ada"), %(coffee 1 "Grace"), %(tea 1 "Linus")];

  // foreach walks anything with elements; destructure as you go.
  foreach (List order in orders) {
    (Symbol item, int count, String who) = order;
    printf("%s wants %d %s\n", who, count, item.str());
  }

  // A pattern condition binds names right where you test them.
  foreach (List order in orders)
    if (order ~= %(tea ?(int n) ?(String who)) && n > 1)
      puts(%"$who is thirsty");

  // Lambdas and iterator chains read left to right.
  Var total = orders.iter().map(%!(List order) => order[1])
    .foldl(0, %!(sum, count) => sum + count);
  assert(total == 4);

  return 0;
}

files
Read the file. Use its contents.


Read a whole file as text or process its lines one at a time. File methods handle the buffers; ordinary String and collection operations handle the contents.


examples/love/files.xlink
#include <stdlib.h>
#include "path.x"

// The checked-in data sits beside the examples wherever they live.
String example_data(String name) {
  Path source = String.new(__FILE__);
  return source.dirname().join("../data", name);
}

int main(int argc, char **argv) {
  String path = argc > 1 ? argv[1]
                        : example_data("love-files/quantities.txt");

  // Read the whole text file and close it in one expression.
  String text = path.open("r").string_close();
  printf("whole file (%d bytes):\n%s", text.len(), text);

  // Or stream lines, keeping the close beside the open.
  auto File input = path.open("r");
  long total = 0;

  // Skip blank lines; each remaining row has three valid longs.
  foreach (String line in input) {
    if (!line.strip()) continue;
    String (a, b, c) = line.words().iter().list();
    long x = atol(a), y = atol(b), z = atol(c);
    total += x + y + z;
  }
  printf("total: %ld\n", total);
  return 0;
}

memory
Working memory has a home.


An auto scope reclaims temporary storage together when its block ends. Nested scopes let a program finish one file before moving to the next, while keeping results in their intended destination.


examples/power/scopes.xlink
/* Allocation counts are zero unless X2C_SCOPE_ACCOUNTING=1 is set, so the
   assertions that expect live allocations check only with accounting. */
#include <assert.h>

int wait_for_day(void) { static int days = 0; return days++ < 2; }

void save_findings(String path, Map findings) {
  Array sizes = findings[<sizes>];
  assert(sizes[0] == 12 && findings[<errors>] == 0);
}

auto int return_early(void) {
  Array files = survey_files();
  return files.length;
}

Array survey_files(void) => ["first.dat", "second.dat"];

void fail_in_scope(void) {
  size_t before = Scope.stats().live_allocations;
  try auto {
    Map findings = inspect_file("failure.dat");
    assert(!Scope.accounting_enabled() ||
           Scope.stats().live_allocations > before);
    raise %(oops);
  }
  catch %(oops): {}
}

Map inspect_file(String path) => {sizes: [12, 24], errors: 0};

int main(void) {
  // Prepare the catch before measuring reclaimable working storage.
  fail_in_scope();
  size_t before = Scope.stats().live_allocations;
  // Reclaim working storage regularly in a long-running survey.
  size_t total = 0;
  // Each day's file list lives until that survey finishes.
  while (wait_for_day()) auto {
    assert(Scope.stats().live_allocations == before);
    Array files = survey_files();
    size_t daily = Scope.stats().live_allocations;

    // Working data is reclaimed after every file.
    foreach (String path in files) auto {
      assert(Scope.stats().live_allocations == daily);
      Map findings = inspect_file(path);
      save_findings(path, findings);
      assert(!Scope.accounting_enabled() ||
             Scope.stats().live_allocations > daily);
      total++;
    }
    assert(Scope.stats().live_allocations == daily);
  }
  printf("processed: %zu files\n", total);
  assert(total == 4 && Scope.stats().live_allocations == before);
  assert(return_early() == 2);
  assert(Scope.stats().live_allocations == before);
  fail_in_scope();
  assert(Scope.stats().live_allocations == before);
  return 0;
}

lists


cons prepends a value while sharing the original List tail. Equal
Lists share canonical structure, making equality a pointer comparison.
List.map, List.filter, and List.foldl compose without changing their
inputs. Nested literals and destructuring keep the resulting data as
readable as the operations that produce it.


examples/love/lists.xlink
#include <assert.h>

int main(void) {
  // Prepend in constant time, sharing the original tail.
  List prices = %(3 5 8), extended = cons(2, prices);
  assert(extended.cdr() == prices && extended == %(2 3 5 8));

  // Compose transformations without changing either input.
  List totals = extended.map(%!(price) => price * 2);
  List selected = totals.filter(%!(total) => total >= 10);

  // Unpack values, then fold them into a single result.
  Var (first, second) = selected;
  Var sum = selected.foldl(0, %!(a, b) => a + b);
  printf("selected: %s + %s = %s\n", first, second, sum);

  // A literal can combine names, computed values, and nested Lists.
  puts(%(total $sum items $selected).repr());
  puts(%"original: $(prices.repr()); extended: $(extended.repr())");

  // car gets the first value; cdr gets the rest, spliced with @.
  List parts = %((first $(selected.car())) (rest @(selected.cdr())));
  puts(parts.repr());
  return 0;
}

arrays


Array combines indexed access, growth, slicing, and functional
operations. Array.copy creates a separate sequence; Array.sort and
Array.reverse mutate it. Assignment shares the object, == compares
contents, and === compares identity. Copies and slices are shallow:
nested objects remain shared.


examples/love/arrays.xlink
#include <assert.h>

int main(void) {
  // Grow and update a sequence in place.
  Array scores = [7, 3, 9];
  scores.push(5); scores[1] += 1;

  // Sorting mutates; copy first to keep the original order.
  Array ranked = scores.copy().sort().reverse();
  assert(scores == [7, 4, 9, 5] && scores !== ranked);

  // Slices and map create new Arrays.
  Array top = ranked[:2];
  Array boosted = top.map(%!(score) => score + 1);
  Var total = boosted.foldl(0, %!(a, b) => a + b);
  printf("scores: %s; ranked: %s\n", scores.repr(), ranked.repr());

  // Use indexed access or iterate over the resulting values.
  foreach (int score in boosted)
    printf("%d ", score);
  printf("=> total %s, best %s\n", total, boosted[0]);
  return 0;
}

maps


Map grows as entries are added, with brackets for reads and updates.
Map.getdefault supplies a fallback without inserting; Map.try_get
distinguishes a missing key from a stored zero. Map traversal order is
unspecified, so this example sorts the keys before printing their values.


examples/love/maps.xlink

int main(void) {
  // Start with named items and their stock quantities.
  Map stock = {"tea": 12, "coffee": 8, "milk": 6, "sugar": 0};

  // Update existing entries or add new ones with the same syntax.
  stock["tea"] -= 2;
  stock["coffee"] += 5;
  stock["cocoa"] = 4;

  // Fetch a value directly, or supply a fallback without inserting.
  printf("tea: %s; biscuits: %s\n",
    stock["tea"],
    stock.getdefault("biscuits", 0));

  // A stored zero is different from an absent key.
  Var sugar;
  if (stock.try_get("sugar", sugar))
    puts(%"sugar is stocked: $sugar remaining");

  // Sort the keys to visit each value in a predictable order.
  Array items = auto stock.keys().array().sort();
  foreach (String item in items)
    puts(%"$item: $(stock[item])");
  return 0;
}

methods


Point.new and Point.move give a user-defined type the same calling
style as the built-ins. Type-qualified names let other types define their
own methods without collisions. Dot notation works for both fields and
method calls; the compiler supplies the receiver argument.


examples/love/methods.xlink
#include <assert.h>
// Define a type with its own named methods.
typedef struct Point { int x, y; } *Point;

// Allocate a Point in the current Scope.
Point Point.new(int x, int y) {
  Point point = xmalloc(sizeof(struct Point));
  point.x = x; point.y = y;
  return point;
}

// Fields and methods both use dot notation.
void Point.move(Point point, int dx, int dy) {
  point.x += dx; point.y += dy;
}

int main(void) {
  // Create and move a Point with compact dot calls.
  Point point = Point.new(1, 2);
  assert(point.x == 1 && point.y == 2);
  point.move(3, 4);
  assert(point.x == 4 && point.y == 6);
  return 0;
}
