AST Grammar

This chapter describes the compiler’s canonical List structures. Use it to read a literal AST construction, a structural pattern, or an AST dump. The source grammar describes tokens; this chapter describes the values those tokens become.

This chapter describes the implementation and may lag behind it; the compiler source is authoritative. The structures are implementation contracts, not a promise that internal representations remain compatible between compiler versions. Language meaning remains in the language reference.

Macro authors should start with macros, meta functions, generating code, and the meta module. x2c translate --dump-ast prints a unit’s AST, and --dump-expansions prints bound macro expansions.

Representation and notation

An AST is an immutable List. Most nodes start with a Symbol discriminant, such as expr, op, or declare. Some intermediate forms have String heads, such as "x2c.quoted". Quotes in the grammar distinguish Strings from Symbols. 0 is an integer. Upper-case words name fields or productions; they are not literal leaves.

Inside the text grammar blocks, | selects alternatives, [...] marks an optional field, and X* repeats a field zero or more times. Parentheses always describe an actual List. Thus (args EXPR*) contains an args head followed by expression children; (ROW*) is an untagged List of rows. These repetition marks are grammar notation, not Match pattern syntax.

() is the empty List, represented by NULL. Depending on its field, it means absence, an empty sequence, an unspecified type, or an empty operand. It is distinct from (nil), the AST content that produces a null List value, and from a Var holding void. Do not assign one meaning to every empty List without reading its enclosing production.

EXPR means a typed expression shell. TYPE means a semantic Type List; BASE means declaration specifier syntax. NODE means syntax appropriate to its position and stage. VALUE means an ordinary Var value; it need not be syntax. A BINDING is the identity record defined below. Source-location, macro-context, and registry data are named separately from program syntax.

A field corresponding to source syntax may already contain derived types, converted operands, generated declarations, and binding identities. Its source origin does not make every descendant source-written. Conversely, constructed Lists use the same structural contracts as parsed source.

Stages and positions

  • Parsing/template: nodes can contain unresolved names, holes, deferred types, or pending applications.
  • Bound: names and expression types have been resolved in compiler state. --dump-ast shows this stage after expansion, not an untouched parse tree.
  • Lowering/generation: transforms replace extensions and add helper, initialization, and cleanup forms. --dump-transforms shows lowered code.
  • Emission: the emitter consumes normalized forms, native fragments, and output decorations, then produces flat C tokens.

The constructed-syntax positions are unit, block, field, enumerator, map-entry, statement, and expression. A block position permits block-item declarations; a governed statement position requires one statement. A node’s layout alone does not establish valid placement, binding, or type. Compiler.bind_syntax and its _bind_form dispatch own placement; ordinary declaration, expression, and statement operations own meaning. Existing types and bindings are trusted, not reconstructed by a second validator. See Macro-visible syntax.

During source control-flow parsing only, Compiler.source_clause supplies Token values for deferred clauses: test, then, else, body, do, init, cond, next, arms, arm, try, catches, catch, and finally. These are addresses into a private parser table. They are transient leaves consumed during binding, not List productions or constructible holes.

Roots, wrappers, and identities

UNIT        ::= (UNIT-ITEM*)
ORIGIN      ::= (at ORIGIN-ID NODE) | (at m-origin NODE)
SOURCE      ::= (src (source FILE BEGIN-OFFSET END-OFFSET) NODE)
API-SOURCE  ::= (api-source LINE DOC NODE)
BINDING     ::= (binding POSITIVE-ID SPELLING)
NAME        ::= SPELLING | (SPELLING) | BINDING
              | (binding-name SPELLING) | (binding-global SPELLING)
              | ("x2c.ident" SPELLING) | NAME-SLOT
METHOD-NAME ::= ((METHOD-OWNER) METHOD-MEMBER)
              | (SOURCE METHOD-MEMBER) | ((construct SOURCE) METHOD-MEMBER)
METHOD-OWNER ::= SPELLING | TYPE-WORD | (SPELLING) | TYPE-SLOT
METHOD-MEMBER ::= SPELLING | NAME-SLOT
CONSTRUCTION-NAME ::= ((construct SOURCE) SPELLING)
TAG-NAME    ::= NAME | () | (gensym ROLE GENERATED-SPELLING)

SPELLING, file paths, and documentation are Strings. POSITIVE-ID is a compiler-issued integer, not an argument number or a source name. Equal spellings in different scopes can have different identities. Generated names can replace the spelling; compiler facts retain a separate source spelling. Do not forge identities. Code.binding_spelling reads their text.

binding-name retains a reference by spelling in a Macro value so it resolves where applied. binding-global retains an explicitly selected file-scope reference. "x2c.ident" requests a spelling that binds where syntax lands. A member name is normally (SPELLING), not a variable BINDING. A Unit-target construction can temporarily attach (construct SOURCE) to a requested name; the declarator owner interprets that requirement rather than treating the captured source as a concrete method owner. Method names have the separate owner/member shape before declaration binding.

at retains a compiler-owned origin index; m-origin is an unresolved anchor in template syntax. src retains exact capture offsets. api-source attaches declaration line/documentation at unit position. The origin table uses (source FILE LINE COLUMN LENGTH OFFSET) records with five payload fields. These are metadata, distinct from the three-payload-field src source record.

Owners: Ast.binding, Ast.without_origin, Ast.rewrap_origin; _resolve_identifier and _identifier_binding; _macro_value_names; Compiler.bind_syntax; _bind_api_source; x2c_ident and Code.binding_spelling; _method_spelling. Consumers preserve identity across expressions, declarations, transformations, and emission. The AST API documents shared operations.

Expressions

Shells, identifiers, and atomic values

EXPR       ::= (expr TYPE CONTENT)
             | (expr () CONTENT)
             | (expr (<macro-expr>) CONTENT)
CONTENT    ::= IDENT | LITERAL | OPERATOR | CALL | ACCESS | GROUPING
             | SELECTION | COLLECTION | INITIALIZER | STRING-CONTENT
             | LIST-CONTENT | LAMBDA | ADAPTATION | PENDING
             | BINDING | EXPR | ORIGIN | SOURCE | NATIVE-CONTENT
IDENT      ::= (ident NAME)
LITERAL    ::= (literal TYPE TEXT) | (literal TYPE TEXT ATOM-VALUE)
             | (literal ("Atom") TEXT (!quote BINDER-ATOM))

() means unresolved or native/unknown type in an expression shell; (<macro-expr>) means resolution must wait for template substitution. Neither is the void type (void). A resolved shell retains a semantic TYPE. Nested expr shells and bare BINDING content are accepted intermediate structures; the resolver can unwrap or resolve them.

TEXT is a String. Numeric and C string literal text retains its spelling; percent String text is decoded. Symbol and Atom literals can also retain an actual Symbol/Atom value in the third field. Generated literals use the same layout. Var absence uses (literal ("Var") "void").

Owners: Compiler.parse_atomic_literal, _symbol_literal, _atom_literal produce literals; Compiler.parse_variable produces names; Compiler.resolve_expression, _content resolve shells and content; _literal emits values. The contents below are children of expr unless a containing production explicitly accepts bare content.

Operators, calls, and access

OPERATOR   ::= (op UNARY-OP EXPR)
             | (op BINARY-OP EXPR EXPR)
             | (op ? CONDITION TRUE-EXPR FALSE-EXPR)
             | (op . EXPR MEMBER) | (op -> EXPR MEMBER)
             | (postfix ++ EXPR) | (postfix -- EXPR)
MEMBER     ::= (SPELLING) | (MEMBER-SLOT)
CALL       ::= (call EXPR ARGUMENTS) | (call C-CALLEE ARGUMENTS)
ARGUMENTS  ::= (args CALL-ARG*)
CALL-ARG   ::= EXPR | DECL | ARGUMENT-SLOT
ACCESS     ::= (index EXPR EXPR) | (getindex EXPR EXPR)
             | (slice EXPR BOUND BOUND BOUND)
BOUND      ::= EXPR | ()

C-CALLEE is a raw String naming a generated/native callee. The source argument order remains the order of args. A source call with no arguments initially has (args (expr (void) ())); generated calls can use (args). The empty void expression is a call convention, not a general absent argument.

index is parsed bracket access. getindex is the resolver’s ordinary indexing form after receiver-specific selection. Slice fields are receiver, start, stop, and step; each omitted bound remains ().

The op field is an operator Symbol, not a separate node type for each punctuation spelling. Member operators put a name List in the final field, not a typed variable reference. The ternary ? is literal punctuation here; in a Match pattern it must be treated according to Match’s quoting rules. The source grammar and operator ledger own the operator inventory and precedence.

Owners: _parse_postfix_apply, _parse_postfix_index, _parse_slice; _operator; _getindex and _slice; _resolve_indexed, _getindex_expression; _call. The bracket-access component selects receiver policy; _emit dispatches to _binary, _unary, _call for normalized forms.

Grouping, type operands, and selection

GROUPING   ::= (parens EXPR) | (parens BLOCK)
             | (sizeof SIZE-OPERAND)
             | (cast DECL EXPR) | (cast TYPE EXPR)
SIZE-OPERAND ::= EXPR | DECL | (parens EXPR) | (parens DECL)
               | NATIVE-SEQUENCE
SELECTION  ::= (generic EXPR ASSOCIATION*)
             | (va-arg EXPR DECL)
             | (offsetof TYPE MEMBER-TOKENS)
             | (type-tag TYPE-SYNTAX)
ASSOCIATION ::= (association TYPE EXPR) | (association default EXPR)
MEMBER-TOKENS ::= (C-TOKEN-OR-EXPR*)

A statement expression retains (parens (block ...)); its final expression statement supplies its type, otherwise it is void. A cast’s first child is a decl during binding and a semantic Type after normalization. Parentheses do not permit a consumer to discard casts when extracting the original operand.

value is T and value is SELECTOR have no head of their own. Parsing builds the $has_type or $has_symbol source form, and resolution replaces it with a runtime test such as a Var_is call. A test that must wait for template substitution keeps the source form under a (<macro-expr>) shell.

offsetof can retain a member designator such as ("field" "." "nested" "[" EXPR "]"). _Alignof has no dedicated AST head: it uses (expr ("size_t") (call "_Alignof" (args OPERAND))), where OPERAND is a declaration or expression.

Owners: _parse_sizeof, _parse_generic, _parse_va_arg, _parse_offsetof, _parse_type_test; _statement_expression, _cast, _sizeof, _generic, _va_arg, _is_type, _is_symbol; Compiler.var_tag_expression. Normalized casts, generic rows, type operands, and member tokens pass to emission. See types and conversions.

Collections, List construction, and String segments

COLLECTION ::= (array EXPR*) | (map MAP-ROW*)
MAP-ROW    ::= (map-entry EXPR EXPR) | MAP-ENTRY-SLOT
LIST-CONTENT ::= (nil) | (cons EXPR EXPR) | (append EXPR EXPR)
               | (splice EXPR) | (var EXPR) | (cache CACHE-ID)
STRING-CONTENT ::= (segments SEGMENT*) | (0)
SEGMENT    ::= (segvar EXPR) | (segexp EXPR) | (cache CACHE-ID)
             | (segraw TEXT)

A call-site rest splice uses (expr ("List") (splice EXPR)). Ordinary List-valued arguments retain their expression form and contribute one value.

Map rows contain key then value; they are not argument Lists. splice retains a value that contributes a sequence. cons and append express runtime List construction; immutable portions can instead become cache references. var is boxing/cache support, not a source keyword.

An empty percent String is (expr ("String") (0)), whose content has an integer head. Ordinary String segments are segvar for $name, segexp for a $(...) expression, and cached text. The interpolation component also accepts segraw text.

Owners: Compiler.parse_list_literal, Compiler.literal_cell; collection literal parsing; Compiler.parse_string_literal, _parse_text_segment; _array_value, _map_value, Compiler.resolve_map_entry, _segments; collection lowering and interpolation lowering. Compiler.cache_cons_cell and Compiler.cache_literal_var produce cache references. Cache payloads are documented below separately.

Initializers and destructuring

INITIALIZER ::= (composite (commas INIT-ITEM*))
              | (dotinit MEMBER INIT-ITEM) | (indexinit EXPR INIT-ITEM)
              | (commas EXPR*)
              | (dstrasgn (targets EXPR*) EXPR)
INIT-ITEM  ::= EXPR | INITIALIZER

Designators can nest, preserving the selected field/index at each step. composite remains an initializer until destination conversion determines its meaning. A destructuring assignment has its targets first and source expression second. The declaration variants are defined under declarations.

Owners: _parse_composite, _parse_designated_init, _parse_assignment_tail; _resolve_initializer, _composite, _destructure; Compiler.convert_initializer and the destructuring component. Native-dependent initval alternatives are internal conversion forms, defined below.

Lambdas and typed adaptation

LAMBDA     ::= (lambda (params LAMBDA-PARAM*) LAMBDA-BODY)
             | (lambda (params LAMBDA-PARAM*)
                 (captures CAPTURE*) LAMBDA-BODY)
LAMBDA-PARAM ::= BINDING | PARAM
LAMBDA-BODY ::= EXPR | BLOCK | BODY-SLOT
CAPTURE    ::= (capture CAPTURE-TARGET TYPE EXPR)
CAPTURE-TARGET ::= BINDING | SPELLING | NAME-SLOT
ADAPTATION ::= (tadapt TARGET-EXPR SOURCE-EXPR)
             | (tadapt ORIGIN-ID SOURCE-EXPR)

Bare lambda parameters initially contain just bindings; lambda binding supplies their types. Empty lambdas can have (params). Capture rows retain the target binding, stored type, and value expression. Reference captures store the address expression and its reference type. Supplied template capture targets can still be spellings or slots before binding.

The two tadapt layouts belong to different stages. Resolution consumes a target typedef expression and produces (expr TARGET (tadapt ORIGIN SOURCE)). The callback lowerer consumes that resolved form. A memo key with the same head is not an adaptation expression.

Owners: Compiler.parse_lambda_literal, Compiler.bind_lambda_expression, _prescribe; lambda lowering; _tadapt; Compiler.lower_typed_adapter_expr. See lambdas.

Declarations, declarators, and types

Declaration forms

DECLARATION ::= (declare BASE BINDINGS) | (typedef BASE BINDINGS)
              | DECL | FUNCTION | (falias DECLARATION NAME)
              | (named-type SPELLING TYPE-SYNTAX)
              | (named-type SPELLING ())
DECL        ::= (decl BASE BINDINGS)
BINDINGS    ::= (bindings DECLARATOR-ROW*)
DECLARATOR-ROW ::= DECLARATOR | (op = DECLARATOR EXPR)
                 | DECLARATOR-ROW-SLOT | (op = DECLARATOR-ROW-SLOT EXPR)
DECLARATOR  ::= (bind DECLARATOR-NAME MODIFIERS)
DECLARATOR-NAME ::= NAME | METHOD-NAME | ()
FUNCTION    ::= (function BASE DECLARATOR FUNCTION-BODY)
FUNCTION-BODY ::= BLOCK | (seq) | BODY-SLOT
DSTR-DECL   ::= (dstrdecl BASE (targets NAME*) EXPR)
              | (dstrdecl (params PARAM*) EXPR)

Unit and block declarations, aggregate fields, and expression type operands share declarator syntax but have different placement rules. Functions and foreign aliases bind at unit position. Destructuring declarations bind at block position. decl is an abstract/type or header declaration without a statement semicolon; it is not interchangeable with declare in every position. named-type is a unit form consumed into ordinary type declarations. An empty name in bind retains an abstract or unnamed declarator.

falias couples an ordinary declaration with its native target binding; emission writes the native alias using the existing type contract. Generation can also produce (declare BASE DECLARATOR) for one prototype, without the usual bindings wrapper. That is an emission form, not an additional constructed-source declaration shape.

Owners: _bind_declaration, _finish_declaration, _bind_targets, _bind_typed_targets; _bind_function and function-body parsing; named-type binding; _prototype; _declare, _function, _foreign_alias; Compiler.enclosing and _ancestor_code.

Modifiers and parameters

MODIFIERS  ::= (MODIFIER-PART*)
MODIFIER-PART ::= MODIFIER | FUNCTION-SUFFIX
FUNCTION-SUFFIX ::= fnmod PARAMETERS MODIFIERS
MODIFIER   ::= * | & | opt-ref | ^ | QUALIFIER
             | (dim) | (dim EXPR) | (bitfield EXPR)
             | (fnmod PARAMETERS) | (fnmod PARAMETERS MODIFIERS)
             | (ATTRIBUTE-TEXT)
PARAMETERS ::= (params PARAM*)
PARAM      ::= (param BASE DECLARATOR) | (...) | PARAM-SLOT
QUALIFIER  ::= const | volatile | restrict

Modifier order states declarator nesting. A function suffix following other suffixes can splice fnmod PARAMETERS MODIFIERS into the enclosing modifier sequence without an extra List shell. Therefore a modifier sequence is not always a flat List of individually tagged modifier entries. The attribute form contains a String of native attribute text. dim without an operand retains an unspecified array bound. The pointer parser accepts a ^ block declarator only while collecting C headers, and Type operations keep it as a declarator modifier. x2c source that writes one is a parse error.

A C no-argument parameter list is explicitly (params (param (void) (bind () ()))). Do not replace it with (params) solely because lambdas and calls permit empty parameter/argument sequences.

A rest parameter List @NAME or Map @NAME uses (param (.... CONTAINER) (bind NAME ())), where CONTAINER is "List" or "Map". Its semantic parameter Type (.... CONTAINER) is one marker, not a modifier on CONTAINER, and is distinct from (CONTAINER); its bound local and emitted native parameter are ordinary CONTAINER values. A key: value call argument is (expr ("Map") (map-entry KEY VALUE)). The final position in the parameter sequence owns the rest convention.

Owners: _declarator, _declarator_suffix, _array_suffix, Compiler.parse_parameter; List.type_from_ast; _declarator and _parameters. Runtime Type operations interpret semantic modifier order.

Source types and semantic Types

TYPE-SYNTAX ::= BASE
BASE       ::= (SOURCE-PREFIX* SOURCE-TAIL)
SOURCE-PREFIX ::= QUALIFIER | STORAGE | inline | meta | MODIFIER
                 | (NATIVE-TEXT)
SOURCE-TAIL ::= TYPE-WORD+ | SPELLING | TYPE-SLOT
               | struct TAG-NAME [FIELDS] | union TAG-NAME [FIELDS]
               | struct FIELDS | union FIELDS
               | enum TAG-NAME [ENUMERATORS] | enum ENUMERATORS
FIELDS     ::= (fields FIELD-ITEM*)
ENUMERATORS ::= (ENUMERATOR*)
ENUMERATOR ::= NAME | DECLARATOR | (op = NAME EXPR)
             | (op = DECLARATOR EXPR) | ENUMERATOR-SLOT
TYPE       ::= (SEMANTIC-PREFIX* SEMANTIC-TAIL) | UNQUAL-TYPE
             | (<macro-expr>) | (.... "List") | (.... "Map")
SEMANTIC-PREFIX ::= QUALIFIER | STORAGE | inline | meta
                   | SEMANTIC-MODIFIER | (NATIVE-TEXT)
SEMANTIC-TAIL ::= TYPE-WORD+ | SPELLING | struct TAG-NAME
                 | union TAG-NAME | struct (TYPE*) | union (TYPE*)
                 | enum TAG-NAME [ENUMERATORS] | enum ENUMERATORS
                 | NATIVE-TEXT (parens NODE)
SEMANTIC-MODIFIER ::= * | & | opt-ref | ^ | (dim) | (dim EXPR)
                    | (bitfield EXPR) | (func (TYPE*))
UNQUAL-TYPE ::= (unqual SEMANTIC-PREFIX* SEMANTIC-TAIL)

A tail expands in place, without adding a List shell. For example, (static struct "Pair" (fields ...)) and (* struct "Pair") have struct in the containing type List, not inside an extra aggregate child. X+ means one or more occurrences.

TYPE-WORD covers the existing scalar specifiers, including void, char, short, int, long, signed, unsigned, float, and double. STORAGE covers typedef, static, auto, extern, register, and threaded. These are components, not independent tagged program nodes. Fields can include declarations, static assertions, and category expansions at the ordinary field parser’s positions. Preprocessor groups retain their existing governed structure.

There is no (type ...) wrapper. Semantic Types flatten declaration base and declarator modifiers. A semantic function type such as ((func ((int) (* char))) void) has two parameter Types and a void result; source fnmod retains parameter declarations instead. Named aggregate conversion retains tag identity, while anonymous semantic bodies contain Types rather than source fields declarations.

Generated native fragments can occur as a complete type sequence, for example ("__typeof__" (parens TARGET)). unqual projects an unqualified value type for inferred declarations and is also recognized by emission. Native fragments do not introduce new language type syntax.

Owners: _tagged_type, _finish_type, enumerator binding; List.type_from_ast, Type.parts, Type.declaration_ast, Type.parameter_ast; type_declaration_parts; Type.function_parts and structural Type operations; Compiler.convert_initializer; _semantic_type, _aggregate, _enum. Use these owners for conversion rather than reconstructing type precedence.

Statements and control flow

Ordinary statements and sequences

BLOCK      ::= (block BLOCK-ITEM*)
BLOCK-ITEM ::= DECLARATION | DSTR-DECL | STATEMENT | ORIGIN | PENDING
              | PREPROCESSOR
STATEMENT  ::= BLOCK | ORIGIN | SOURCE | PENDING | (stmnt EXPR) | (empty)
             | (group NODE*) | (seq NODE*)
             | (return) | (return TYPE EXPR) | (return EXPR)
             | (if EXPR STATEMENT) | (if EXPR STATEMENT STATEMENT)
             | (while EXPR STATEMENT) | (do STATEMENT EXPR)
             | (for FOR-INIT OPTIONAL-EXPR OPTIONAL-EXPR STATEMENT)
             | (switch EXPR STATEMENT) | (case EXPR) | (default)
             | (break) | (continue) | (goto NAME) | (label NAME)
             | (defer STATEMENT) | RAISE | TRY | MATCH
FOR-INIT   ::= DECL | DECLARATION | EXPR | ()
OPTIONAL-EXPR ::= EXPR | ()
PREPROCESSOR ::= (preproc TEXT)

block introduces braces/scope; group retains governed preprocessor structure without adding braces. seq splices syntax items at unit/block boundaries. It is consumed there during binding/lowering, not emitted as a special C statement. A sequence is not automatically legal as one governed statement.

(return) has no value. Bound value returns retain the function’s target TYPE, as (return TYPE EXPR); lowering converts the operand and removes that field, yielding (return EXPR). The same head therefore has three legal layouts. At emission only, stmnt may also wrap lowered statement content, such as (stmnt (return EXPR)) from a generated callable helper; the emitter appends a semicolon.

Owners: Compiler.finish_return_statement, Compiler.parse_governed, _block_items, _goto_statement; _bind_form and control binders; _return; _sequence_tail; _rewrite and transfer lowering; _emit and _leaf. The source-form helpers name selected layouts for construction and recognition, not the whole grammar.

Match, raise, and catch rows

RAISE      ::= (raise EXPR (args DETAIL-EXPR*))
TRY        ::= (try STATEMENT CATCHES-OR-EMPTY FINALIZER-OR-EMPTY)
CATCHES-OR-EMPTY ::= () | (catchcases (CATCH-ROW*) BINDING)
CATCH-ROW  ::= (PATTERN-EXPR STATEMENT) | (() STATEMENT) | CATCH-SLOT
FINALIZER-OR-EMPTY ::= STATEMENT | ()
MATCH      ::= (match EXPR (MATCH-ROW*))
MATCH-ROW  ::= (PATTERN-EXPR ARM-BODY) | ((*) ARM-BODY)
             | PREPROCESSOR | MATCH-ROW-SLOT
ARM-BODY   ::= STATEMENT | (guarded STATEMENT)
PATTERN-TEST ::= (expr () (matches EXPR PATTERN-EXPR TYPED-CAPTURES))
              | (expr (int) (matches EXPR PATTERN-EXPR BLOCK VISIBLE-BINDINGS))
MATCH-IF   ::= (match-if EXPR (PATTERN-EXPR STATEMENT))

Raise arguments alternate detail-key expressions and value expressions. A catch’s default pattern is (); a match default is the raw List (*). Other patterns are expressions producing Match data. Pattern operators and capture binders inside that data are not additional AST node kinds.

catchcases retains the generated handler binding after its ordered arm List. Match rows can interleave preprocessor directives. Guards initially become an if whose successful block ends with break; typed captures can wrap this with declarations before (guarded STATEMENT) is applied. Therefore guarded does not require an immediate if child. Match and catch bodies can already contain generated capture declarations at the bound stage.

~= parses as matches expression content. Binding replaces its typed capture descriptions with capture declarations and (BINDING TYPE) rows. The rows expose the existing identities only to successful continuations. Positive && and if lower to nested conditions. Their internal match-if uses ordinary match tests without a switch or implicit break. A predicate used as a value wraps those conditions in a statement expression returning an int. Constructed (expr () (op ~= EXPR PATTERN-EXPR)) also enters the same pattern binder.

Owners: _raise_statement, _catch_cases, _match_cases, Compiler.parse_case_body; _bind_catchcases, _bind_try, _bind_match; try lowering; match lowering; raise lowering. Cleanup consumes landing/defer forms below; the emitter handles surviving raise nodes. See Match and Errors and cleanup.

Compile-time and intermediate forms

These values explain literal Lists in compiler and runtime source. Their presence here does not make every carrier available at source unit position.

Pending applications and captures

PENDING    ::= (macro-invoke DEFINITION-REF INVOCATION-INPUT SITE)
             | (macro-slot SPLICE-FLAG META-EXPR)
             | (macro-slot SPLICE-FLAG META-EXPR SLOT-CONTEXT*)
             | (macro-bind PROJECTION-ATOM)
             | (meta-call EXPR ARGUMENTS)
             | (meta-cap PROJECTION-ATOM) | (meta-cap (PROJECTION-ATOM))
             | (tpl-call DEFINITION-OR-EXPR ARGUMENTS)
             | (macro-value MACRO-DEFINITION)
DEFINITION-REF ::= MACRO-DEFINITION | NAME-ATOM
                 | (!quote MACRO-DEFINITION) | (local-macro NAME-ATOM)
INVOCATION-INPUT ::= (args INVOCATION-CAPTURE* [FRESH-INPUT])
                   | (target (args INVOCATION-CAPTURE*)
                       INVOCATION-CAPTURE [FRESH-INPUT])
FRESH-INPUT ::= (fresh INVOCATION-CAPTURE*)
INVOCATION-CAPTURE ::= (capture (source VALUE) (value VALUE)
                         (expression VALUE) (splice VALUE*) REQUIREMENT*)
                     | (capture (source VALUE*) (value VALUE*) REQUIREMENT*)
SITE       ::= TOKEN | m-invoke
SLOT-CONTEXT ::= (construct VALUE) | (target VALUE)

The first capture alternative is scalar; the second is a sequence capture. These assoc-row capture records differ from lambda captures. META-EXPR is a meta-expression List. SPLICE-FLAG states scalar versus sequence insertion. The parser produces the three-element slot without trailing context rows. The consumer also accepts the displayed SLOT-CONTEXT rows in constructed slots; no current slot parser produces those rows.

REQUIREMENT is a construction-projection binder or (construct SOURCE) record attached to Unit-target capture rows, not another operand of the source expression. Unit invocation captures still produce these requirements.

Projection atoms identify a hole and one of its source/value/expression/splice views. meta-cap can hold the atom directly or inside a List, depending on whether the containing List itself is the required value. A template call can name a stored definition or carry a callee expression. Within a template, a pending invocation can retain its descriptor as (!quote MACRO-DEFINITION); that quotes the descriptor data, not its resulting program syntax. These forms are consumed or retained according to template stage, not emitted as C calls.

Owners: _invocation_node and _stored_reference; _parse_meta_call, _meta_argument, _expression_invocation, _template_call; _scalar_row, _sequence_row, _forwarded_capture; Compiler.try_parse_macro_slot; Compiler.expand_macro_invocation_node and _bind_expansion; expression resolution and Compiler.meta_argument consume meta projections and calls.

String-headed syntax values and quotation

APPLICATION ::= ("x2c.template" MACRO-DEFINITION (VALUE*))
QUOTED      ::= ("x2c.quoted" . NODE)
              | ("x2c.quoted" (QUOTED-FRESH-ROW*) NODE)
QUOTED-HOLE ::= ("x2c.hole" REDUCED-HOLE PROJECTION VALUE)
REDUCED-HOLE ::= (macro-param (kind HOLE-KIND) (sequence FLAG))
QUOTED-ANCHOR ::= ("x2c.at" NODE)
IDENTIFIER-VALUE ::= ("x2c.ident" SPELLING)
QUOTED-FRESH-ROW ::= (BINDER SPELLING FILE-LINKAGE-FLAG)
PROJECTION ::= source | value | expression | splice | member | shell

In the completed form, . NODE denotes the tail itself: cons the String tag onto the canonical node. Constant quotations can share the literal cache’s node and carrier. The three-field form retains supplied values whose projections, private names, or source information still use placement. Its hole records do not represent arguments waiting to be supplied.

A NAME-SLOT, TYPE-SLOT, MEMBER-SLOT, BODY-SLOT, or category row slot in the preceding productions is a macro-bind or macro-slot in that parser position. A sequence projection can occupy a complete row/child sequence; it does not change the enclosing production after expansion.

The application contains one grouped value per formal hole; a sequence formal’s remaining values occupy one List. A quotation holds its fresh-name rows and syntax. A quotation fresh row marks whether a file-scope row declares the name with linkage. Each reduced hole records kind and sequence status, without its descriptor’s binder row. shell denotes expression-shell insertion. Quoted anchors acquire the landing context’s origin as required; they are not verbatim C text despite their String heads.

Owners: Macro_apply and _group; _construction, _built_item, _built_hole; Compiler.land_quotation, _fill_syntax, _splices, _project_hole, _helper_result. Runtime recognition and pattern projection handle these structures as well as bound AST names and expression shells. See quotation semantics.

Macro definitions

MACRO-DEFINITION ::= (macrodef DESCRIPTOR-ROW*)
DESCRIPTOR-ROW ::= (name NAME-ATOM) | (kind RESULT-KIND)
                 | (target TARGET-KIND-OR-ZERO) | (targetp HOLE-OR-EMPTY)
                 | (parameters (HOLE*)) | (fresh (TEMPLATE-FRESH-ROW*))
                 | (captures (BINDING*)) | (pattern MATCH-PATTERN)
                 | (template NODE) | (rebuild REBUILD-OR-EMPTY)
                 | (leaf FLAG) | (origin LOCATION) | (file PATH)
                 | (builtin FLAG) | (local FLAG) | (static FLAG)
                 | (env (ENV-ROW*))
HOLE       ::= (macro-param (binder BINDER) (kind HOLE-KIND) (sequence FLAG))
TEMPLATE-FRESH-ROW ::= (BINDER SPELLING META-READ-FLAG)
REBUILD-OR-EMPTY ::= () | (REBUILD-SYNTAX (REBUILD-KEY-ROW*))
REBUILD-KEY-ROW ::= (SOURCE-KEY VALUE-KEY EXPRESSION-KEY SPLICE-KEY
                    RETURN-KEY DECLARATOR-KEY)
ENV-ROW    ::= (IDENTITY VALUE)

--dump-ast prints a definition as (macrodef <macro NAME>). The definition producer writes one of each descriptor row except env; Macro_close can append the captured environment. Consumers use assoc lookup, not the physical row order. Kind and target categories select ordinary parser/binder positions. FLAG is an integer flag. A full fresh row’s flag marks meta-call name use; quotation construction derives the fresh rows it needs for landing. Each rebuild key is a projection binder or the Symbol ? for an unused projection. Parameter rows precede the decorator target row. Environment identities normally use (binding-name SPELLING), preserving references across translation contexts. Rebuild and environment rows are descriptor data, not another program production.

Macro is a singular hole and decorator target kind. A capture carries the canonical Macro value. Nested definitions give their own holes distinct binder identities while retaining source spellings for lookup and diagnostics. Returning a bare macrodef during decoration is a Macro transformation; returning a Decorator value continues onto its following target. A generated seq instead uses the captured macro’s result kind. Declaration and collected Unit sequences retain the ordinary declaration-bundle production, including empty output and several mapped applications.

Global definitions bind at unit position; local definitions bind in blocks. The macro registry wraps an imported definition as (imported-macro FROZEN-DEFINITION).

Owners: _definition_node, _fresh_rows, _rebuild_template, _rebuild_keys; definition reading; Macro_close; _bind_macrodef. The source grammar owns category spellings; this chapter documents their stored forms.

Code values and effects

CODE-VALUE ::= (code-value STAGE CODE (EFFECT*))
STAGE      ::= "source" | "bound" | "lowered"
EFFECT     ::= (rewrite POINT KIND NAME SHAPE HOLES)
             | (new-name TOKEN ROLE-STRING) | (cleanup TOKEN PLACED-CODE)

Compile-time scalar results enter ordinary syntax through Compiler.lift_meta_expression and Compiler.bind_meta_statement. A source carrier requires ordinary binding. A bound or lowered carrier retains completed work. Effects apply in order within the macro application’s transaction; new-name and cleanup tokens are replaced in CODE. Retained declaration production

DECLARATION-PRODUCTION ::= (declaration-bundle (rows NODE*))
                         | (syntax-recipe CALLBACK ARGUMENTS-VALUE)
                         | (declaration-recipe CALLBACK ARGUMENTS-VALUE)
                         | (default FUNCTION)
                         | (default-forward CHILD PARENT MEMBER FALLBACK*)
                         | (declaration-pending CALLBACK ARGUMENTS-VALUE
                             MACRO-STACK PRIVACY)
                         | (declaration-forward CHILD PARENT MEMBER
                             (FALLBACK*) PRIVACY)
                         | (declaration-default FUNCTION MACRO-STACK PRIVACY)
                         | (declaration-function DECLARATION BODY MACRO-STACK)
                         | (declaration-initialized DECLARATION MACRO-STACK)

Bundles, declaration recipes/defaults, and collected function/initializer carriers are unit forms. syntax-recipe instead uses the caller’s position. Collected functions retain one declared function, its body, and the macro context needed to bind it later. Collected initialized declarations likewise retain that context. Defaults and forwarding candidates are selected by the existing declaration owner before binding the selected bodies. ARGUMENTS-VALUE is callback data, not necessarily an AST args node.

Owners: _construct; _bind_bundle, _bind_recipe, _bind_decl_recipe, _bind_default; collected function production; collected initializer production; Compiler.select_declaration_defaults, _produce_rows, _select, _forward; _retain_bundle and Compiler.replay_declaration_source. See named types and declaration production.

Declaration bundle rows

A Declaration macro, or a NamedType decorator, produces declarations once while the owning source’s public declarations are collected. Its result is retained for full binding; the producer is not evaluated again to obtain its bodies. Nested declaration producers share this rule. Static publication and ordinary dependency invalidation apply to the retained result. Imported and cached declarations publish the selected signatures of their owning source.

The canonical container is (declaration-bundle (rows ITEM ...)). Rows may include ordinary top-level syntax and these constructible forms:

  • (default FUNCTION) supplies a function candidate. An ordinary declaration of that exact function in the owning source wins, including a later one. Only the selected body is bound. A candidate produced by a static type declaration has static linkage. Two ordinary definitions still conflict.
  • (declaration-recipe CALLBACK ARGUMENTS) defers a meta producer until the owning source’s declarations are available. It is evaluated once, and its declarations join the same bundle.
  • (default-forward CHILD PARENT MEMBER FALLBACK) selects an ordinary parent method after signatures are collected and supplies a child forwarding method. FALLBACK is an optional function candidate when no parent applies.
  • (syntax-recipe CALLBACK ARGUMENTS) supplies syntax when a retained body is bound, allowing it to use the selected method signatures.

Retained bodies also carry the usual macro bindings and source locations for diagnostics. A consumer cannot replace a provider’s exported default by defining another function with its name.

Imports, protocols, and static assertions

IMPORT     ::= (import PACKAGE-STRING ALIAS-STRING)
ASSERTION  ::= (c-assert) | (c-assert EXPR EXPR)
PROTOCOL   ::= (protocol PROTOCOL-RECORD STORAGE-MODE LOCATION)
PROTOCOL-RECORD ::= ("protocol-record" BASE PARTICIPANT-STRING
                     (associated ASSOCIATED-ROW*) (members MEMBER-ROW*))

             | (adopt BASE TYPE STORAGE-MODE TYPE LOCATION)
             | (adopt BASE TYPE STORAGE-MODE (tag EXPR) LOCATION)

Imports are parser-retained unit items; the alias defaults to the package name. The constructed-syntax binder does not directly accept an import node; import replay uses its owning effect path. Imported member selection is retained separately, without extending the import node. c-assert with operands is legal at unit, block, or field position; the empty form is a shallow-collection marker without the discarded operands. Protocol and adoption forms are unit items, with associated types and members held in ordered record rows. The extended adoption adds a representation or a tag expression; the existing protocol rules determine which applies.

A conform node is never program syntax. The compiler presents each resolved conformance that needs generated support to the protocol adapter rule as one conform node, and the rule places the forwarding members, descriptor thunks, method table, and descriptor registration. Each PART asks for one generated declaration: (default NAME STORAGE), (inherited NAME EXPECTED), or (thunk NAME ERASED). The comment above protocol_conformance in src/components/protocol-adapters.x defines every field.

Native-dependent initializer alternatives

INITVAL    ::= (initval [(input INPUT-ROW*)] INITIALIZER-CHOICE*)
INPUT-ROW  ::= (FORMAL EXPR)
INITIALIZER-CHOICE ::= (CONDITION PATH DESTINATION-TYPE VALUE-EXPR)
CONDITION  ::= EXPR | ()
DESTINATION-TYPE ::= TYPE | ()

An initval is conversion content under an expression shell. Its optional input header captures the source operands once for native alternatives. Cleanup, initialization, and generated markers

LOWERED-NODE ::= (localinit STATIC-DECL BLOCK) | (sourceinit FUNCTION)
               | (initcode (input INPUT-ROW*) (NODE*))
               | (staticinit BINDING INITIALIZER-VALUE)
               | (defer STATEMENT ENVIRONMENT CALLBACK
                   (CAPTURE-RECORD*) (BINDING*))
               | (landing CODE (LANDING-ROW*))
               | (function BASE DECLARATOR BODY kernel)
               | (try STATEMENT () STATEMENT kernel)
STATIC-DECL ::= DECLARATION | (at ORIGIN-ID STATIC-DECL)
ENVIRONMENT ::= BINDING | ()
CALLBACK    ::= BINDING
CAPTURE-RECORD ::= (BINDING STORAGE-TYPE FIELD-BINDING)
LANDING-ROW ::= (new-name BINDER ROLE-STRING) | (outer BINDER NODE)
              | (exits BINDER CODE) | (region BINDER NODE)

The extended defer holds its callback environment, capture records, and written bindings until cleanup places its calls on exits. The simple source defer has only one body child. localinit owns a local static declaration and the remaining block; staticinit wraps its initializer with a cleanup binding. sourceinit retains a generated unit-initializer function. initcode packages initializer input with its untagged statement sequence for a native macro body. The declaration in localinit can retain origin wrappers, which its emitter removes before reading the declarators.

A landing executes rows in order. new-name introduces a binding; outer lowers in the enclosing context; exits supplies cleanup for subsequent regions; region lowers its body within that cleanup context. Binder atoms are temporary substitution keys, distinct from positive binding IDs. CODE can be pending quotation/application syntax before cleanup binds it.

The literal kernel marker selects shipped rules for a generated function or a fallback try region. The transform removes the marker before emission. It is neither another body child nor a new source keyword.

Owners: Compiler.rewrite_defer_list, Compiler.lower_defer_region, _callable_defer, _landing_region; _static_regions, _static_initializers; _lower_defer, _lower_landing, _inside, Compiler.lower_cleanup; _try_landing; _written_function; source initialization and initializer assembly; _local_static, _static_binding, _source_initializer, _initializer_macro.

Placed code and match tests

PLACED     ::= (placed NODE)
MATCH-TEST ::= (m-all TEST*) | (m-any TEST*)
             | (m-next CURSOR PRIOR) | (m-step CURSOR PRIOR)
             | (m-take LOCAL CURSOR) | (m-bits CURSOR BITS)

Match lowering writes code that is already lowered. placed wraps a lowered match switch or arm. The transform lowers only the source parts that the active lowering watches inside it and renders the rest as C text; emission prints NODE. The match tests are C conditions over List cells. m-all and m-any join two or more tests with && and ||. m-next assigns the cdr of PRIOR to CURSOR and holds, while m-step makes the same assignment and tests the new cursor. m-take assigns the car of CURSOR to LOCAL and holds. m-bits compares the u64 bits of the car of CURSOR with the uint64_t literal BITS.

Owners: src/components/pattern-match.x writes these forms, _placed in src/transform/traversal.x lowers placed code, and src/emit/dispatch.x emits both.

Cache payloads and compatibility content

                | (cons CACHE-VALUE CACHE-VALUE) | (nil)

Native sequences, decorations, and output tokens

NATIVE-CONTENT ::= NATIVE-TEXT | NATIVE-SEQUENCE | ()
NATIVE-SEQUENCE ::= (NATIVE-ELEMENT*)
NATIVE-ELEMENT ::= C-TOKEN | NODE
DECORATION ::= (comment TEXT*) | (space TEXT*)
SOURCE-MAP-OUTPUT ::= src-at ORIGIN-ID C-TOKEN* src-at PREVIOUS-ORIGIN-ID

Generated forms can mix raw String C text and typed nodes, rather than add an AST tag for each C fragment. _emit handles these structures as follows:

  1. An empty List emits nothing.
  2. A List with a non-Symbol head enters _sequence. Each non-Symbol element is visited in order; List elements recurse and other leaves pass through. If the remaining tail begins with a Symbol, that tail is one node.
  3. Storage, qualifier, and inline prefixes are emitted before the rest, except typedef, which has dedicated declaration handling. threaded becomes _Thread_local.
  4. Known heads dispatch to their node operations. Unknown Symbol heads use _leaf’s generic rule: emit the head followed by its recursively emitted tail. This permits existing C-shaped generated fragments.

This fallback is part of the representation contract. A finite inventory of named heads alone cannot describe every emitted fragment. It also does not make an arbitrary List valid at a constructed-source position: the binder has its own position contracts.

comment and space are presentation nodes. preproc retains source-order text and rewrites x2c include targets during emission. src-at belongs to the flat output token stream consumed by formatting, not source AST input. Match lowering constructs ordinary blocks, switches, and native sequences.

Owners: _emit, _sequence, _prefix, _leaf; _banner, _header_guard, _source_unit, _vertical_spacing; _match_lowered; source mapping and formatting.

Reading concrete layouts

The type initializer fixture contains this bound return, shown with compact whitespace:

(return (int) (expr (int) (literal (int) "42")))

Its first payload field is the return context, not the value. Lowering converts the expression to that context and leaves:

(return (expr (int) (literal (int) "42")))

The same fixture contains a no-argument call’s (args (expr (void) ())). The AST leaf fixture contains a pointer-to-function declarator:

(bind (binding 4 "ast_phase1_UnaryPointer")
  (* (fnmod (params (param (int) (bind () ()))))))

The pointer mark and function modifier are siblings in MODIFIERS. The function parameter retains its base type and unnamed declarator; it is not yet the semantic function modifier (func ((int))).

The captured lambda fixture shows typed parameter rows, capture storage types, and reference capture expressions. The catch fixture shows that catch patterns are typed List expressions and that the handler follows the complete row List. These children cannot be interpreted by looking only at a capture or args head.

Dynamic heads and forms without a head

Operators vary in the op field; aggregate kind selects struct or union; source/semantic type Lists can start with a type name or modifier. Native sequences can start with String text, another List, or numeric zero. Argument, parameter, arm, capture, initializer-choice, environment, and path rows can be untagged. Their enclosing productions determine how to read them.

For example, a pattern (expr TYPE (call CALLEE (args ...))) first establishes the typed shell, then the call content, then its ordered arguments. A pattern on (return TYPE EXPR) is recognizing the bound return stage; the lowered stage no longer has that type field. A match on (capture ...) must know whether it is reading a lambda capture or a macro invocation capture. Use this chapter’s production and stage together when reading such patterns.
