Iter

Iter.parallel_map

ParallelMap Iter.parallel_map(Iter i, ThreadValueFn function, int workers)

Describes mapping function over source with at most workers Threads. Nothing runs until ParallelMap.foldl consumes the operation. The descriptor belongs to the caller’s Scope and borrows the source iterator storage and callback code. Those must remain live until the fold ends. Source values follow Thread.start borrowing: their input graphs must remain live and read-only while outstanding workers use them. A source must not mutate or recycle an outstanding input’s storage.

Raises: <bad-arg> for a null function or a nonpositive worker count, or <alloc-fail> for descriptor storage.

Source: lib/thread.x

Iter.parallel_map_in

ParallelMap Iter.parallel_map_in(Iter i, Pool pool, ThreadValueFn function, int workers)

Maps with a borrowed canonical-value pool active inside each callback. The pool and its ancestors must stay live until foldl finishes. The caller retains ownership; workers restore their previous pool without releasing the borrowed pool. Source traversal and accumulation use the caller’s pool.

Raises: <bad-arg> for a null pool or function or a nonpositive worker count, or <alloc-fail> for descriptor storage.

Source: lib/thread.x

ParallelMap

ParallelMap.foldl

Var ParallelMap.foldl(ParallelMap map, Var seed, Func accumulate)

Folds borrowed worker results on the caller in completion order. Reuses at most the configured worker count. A worker keeps its callback Context alive and waits while the caller consumes its result. The next assignment or shutdown releases that Context and its remaining storage. No result graph is exported. To retain worker-owned storage, the reducer must explicitly move it to its own owner before returning. References, including cycles, do not imply ownership. Borrowed input owners stay live through the fold; callbacks must not mutate outstanding borrowed inputs. Workers use the shared canonical pool. Explicit private pools retain their own lifetime rules.

A void seed takes the first result without calling the reducer. That result must survive worker cleanup independently; use an explicit seed and transfer in the reducer for worker-owned storage. Empty input or a null descriptor returns the seed. Source traversal and accumulation run on the caller; each worker holds at most one job or unread result. Every exit stops and joins remaining workers. Channel waits cooperate with stop; arbitrary computation and native I/O need not. Cleanup keeps the primary Error. Native join failure leaving a worker live aborts.

Raises: source, start, worker, allocation, accumulator, or stop causes, including <void-op> for a void worker result.

Source: lib/thread.x

Thread

Thread.finish_all

void Thread.finish_all(Array pending)

Joins and frees every worker in pending, discarding returned results. A null or empty Array does nothing. Already-joined handles are freed. Successfully consumed handles are removed, including workers whose join reported a worker or captured-error export error. Native join failure leaves its handle in pending for retry. All other entries are attempted. Entries must be unique, valid handles exclusively owned by this caller, with no concurrent mutation, joining, or freeing. Failures are collected and raised as <join-fail> only after cleanup. During an existing Error unwind, the original Error continues unchanged: consumed workers’ failures are dropped, and a native stderr diagnostic reports only handles that remain unjoined.

Raises: <join-fail> containing the captured join failures, including <bad-arg> for a null entry or <bad-state> for a joining entry. Error snapshot failures use the existing raw Error floor.

Source: lib/thread.x

Thread.finish_any

Var Thread.finish_any(Array pending)

Waits for one worker, joins it, frees its handle, and returns its result. A null or empty Array returns void. Selection and exclusive ownership follow Thread.wait_any. Result ownership is unchanged, as with Thread.join. The worker must explicitly preserve output before callback exit. A consuming join removes and frees the handle even when worker failure or captured-error export raises. Native join failure retains the handle in pending for retry. Other entries keep their relative order; a retained selected handle moves to the end.

Raises: the same causes as Thread.wait_any and Thread.join.

Source: lib/thread.x

Thread.free

void Thread.free(Thread t)

Frees a Thread handle after its consuming join has completed. NULL does nothing.

Raises: <bad-state> for running or joining handles.

Source: lib/thread.x

Thread.join

Var Thread.join(Thread t)

Joins a worker and returns its result bits without ownership changes. The callback must have preserved any referenced output before exiting. Native join failure leaves the handle joinable. Concurrent or repeated joins are rejected. Once native join succeeds, the handle is consumed, including when a captured worker Error is raised. Free it after the join returns or after catching that Error. Void results remain void.

Raises: bad-arg for NULL, bad-state for an active or completed join, io-fail for native join failure, error-export causes, or join-fail containing the captured worker errors.

Source: lib/thread.x

Thread.run

void Thread.run(Array jobs, Func completed)

Runs zero-argument jobs concurrently and waits for all of them. Each successful result, including void, reaches completed on the caller when that callback is nonnull. Result bits carry no ownership transfer. Each job must explicitly preserve referenced output before returning; completed runs after that job’s temporary storage has been reclaimed. Jobs, captures, and borrowed storage stay live through the call. Separate output scopes permit exclusive worker access; a shared allocation scope is not made safe by this API. Canonical values use the shared process pool. Explicit private pools retain their own lifetime rules. The completion callback must not wait on participant progress.

Startup, job, callback, or coordinator-stop failure requests stop on all remaining jobs before joining any. Cleanup preserves the original Error and invokes no completion callbacks. Stop is cooperative: native I/O and computation that never checks stop can delay completion. Native join failure aborts if cleanup cannot establish that borrowed storage is idle.

Raises: startup, callback, captured-error, stop, or worker join causes.

Source: lib/thread.x

Thread.start

Thread Thread.start(ThreadValueFn function, Var value)

Starts one Var-to-Var worker. Input and result bits are copied without cloning, exporting, or transferring referenced storage. Input storage and callback code stay live through join. Shared mutable data requires caller coordination. The callback must explicitly preserve any output it retains beyond exit; use separate output owners for concurrently running workers. Shared canonical Strings and Lists survive worker exit. Wide boxed values still require their backing allocation to survive. Thread.start_raw accepts copied byte-buffer input instead.

Raises: bad-arg for a null callback, or Thread.start_raw causes.

Source: lib/thread.x

Thread.start_raw

Thread Thread.start_raw(ThreadFn function, const void *input, size_t input_size)

Starts one worker and returns its heap-owned handle. input_size bytes are copied before native start and passed once to the callback. Pointees within those bytes remain shared and must outlive the worker. Copied storage has max_align_t alignment, so over-aligned input types are unsupported. A worker runs on an 8 MiB stack on every platform, so library recursion limits are reached the same way on a worker as on the main thread. The worker also adopts this thread’s Error policy, so a cause set to <ignore>, <log>, or <collect> resumes inside the callback as it does here. An attempt that reaches pthread_create permanently enables canonical-pool locking; the first successful start also freezes Var descriptor registration.

Raises: <bad-arg> for a NULL function or missing nonempty input, <size-limit> when the handle size or shutdown-hook registry overflows, <alloc-fail> when the handle or shutdown hook cannot be allocated, or <io-fail> when pthread_create fails. Failure during native once initialization or mutex setup aborts the process.

Source: lib/thread.x

Thread.stop

void Thread.stop(Thread t)

Requests cooperative stopping without closing any Channel. The request persists and wakes a registered Channel or completion wait. Computation and arbitrary native I/O are not interrupted. Repeated requests are safe while the handle remains live; stop does not join or free it.

Raises: <bad-arg> for a null handle.

Source: lib/thread.x

Thread.wait_any

Thread Thread.wait_any(Array pending)

Waits for a finished worker, removes its handle from pending, and returns it. A null or empty Array returns NULL. If several workers have finished, the first in current Array order wins; completion chronology is not recorded. A failed worker is also ready. This does not join, export results, or free the handle: the caller must still call Thread.join and Thread.free. join reports worker errors as usual. Entries must be unique, valid Thread handles. The caller exclusively owns this Array and its handles throughout the wait; concurrent mutation, joining, or freeing is unsupported. A returned unjoined handle may be added again and selected again. Freed handles must never be supplied.

Raises: <bad-arg> for a null entry, or <bad-state> for a joining or joined entry. Native completion synchronization failure aborts.

Source: lib/thread.x

ParallelMap

typedef struct ParallelMap *ParallelMap

Scope-owned description of a bounded parallel mapping operation. Construction starts no workers. The source iterator storage and callback are borrowed until a consuming ParallelMap.foldl finishes. Use temporary iterator chains only when the fold is in the same full expression.

Source: lib/thread.x

Thread

typedef struct Thread *Thread

A heap-owned native worker handle with one consuming join. A started Thread must be joined, including after its callback finishes, and then released with Thread.free.

Source: lib/thread.x

ThreadFn

typedef Var (*ThreadFn)(const void *input, size_t input_size)

Computes a result from borrowed start-input bytes, valid during the call. The return copies bits without exporting or transferring storage. Preserve output explicitly before callback exit; temporary storage is then freed. Workers start in the shared canonical pool. Explicit private pools retain their own lifetime rules. An escaping Error becomes join-fail at join; policies that resume still resume inside the callback.

Source: lib/thread.x

ThreadValueFn

typedef Var (*ThreadValueFn)(Var input)

Computes a result from borrowed Var input. Thread.start copies the return bits; retained storage must already outlive callback exit. ParallelMap instead keeps callback storage alive through its reducer, which explicitly transfers anything it retains. Input storage stays live through use.

Source: lib/thread.x

Design notes

Thread copies input and result bits. Callbacks explicitly preserve any output that must outlive their private work storage. Errors are captured separately for join; parallel reducers borrow from parked workers.
